一、总体结果概述
-----------------------------------------------------------

本次评估发现：
  - 所谓"圆孔/腰孔/矩形孔/视图检测准确率低于 50%"的现象，
    主要是因为采用"图像级完全匹配（per-image perfect match）"
    这一极严苛指标。
  - 若改用"实例级 F1（per-instance F1）"，绝大多数类别的指标
    实际表现良好（0.88 ~ 1.00）。
  - 真正的根因有两类：
      (1) 训练阶段未覆盖 "Group" 标签 -> 圆孔/腰孔/矩形孔
      (2) Notes 标注一致性差 + 罕见正交视图样本不足 -> 视图检测

四、低准确率根因分析
-----------------------------------------------------------

【根因 1】Group 类标签未参与训练（影响：圆孔/腰孔/矩形孔）

在 prepare_dataset_swift.py 的 FEATURE_CATEGORIES 中只包含
"Round Hole / Rectangular Hole / Slotted Hole / Threaded Hole /
 Fillet / Bending / Silver Plating" 等 7 个类别，
不包含 "Round Hole Group / Rectangular Hole Group /
 Slotted Hole Group" 等组合标签。

但是真值 788_11Feats_View.json 中包含：
  - Round Hole Group:        479 个（测试集 43 个）
  - Slotted Hole Group:      348 个（测试集 37 个）
  - Rectangular Hole Group:  278 个（测试集 29 个）

模型从未见过这些 Group 标签，所以根本不可能预测出来。
任何含有 Group 标签的图像 -> 该任务的图像级完全匹配必然失败。

验证：若评估时排除 Group 标签，图像级准确率立即变为：
  - rectangular_hole:   4% -> 100%
  - slotted_hole:      23% -> 94%
  - round_hole:        39% -> 96%

==> 这不是模型问题，而是训练数据范围与评估真值范围不匹配的问题。


【根因 2】视图检测的两个独立问题

视图检测每张图平均含 ~9 个标签，即使实例级 F1 = 0.88，
图像级完全匹配的概率约为 0.88^9 ≈ 31%（与实测 36% 吻合）。

具体错误来源（按贡献从大到小排）：

(a) Notes 标注不一致 —— 占视图错误总数约 58%
    在测试集 300 个 Notes 真值中：
      - 33 个完全没被检测到（FN）
      - 30 个位置正确但 IoU < 0.4（边界范围分歧）
      - 36 个为模型多余预测（FP）
    Notes 平均 IoU 仅 0.79（所有视图类中最低），
    最小 IoU 仅 0.40（卡在阈值边缘）。

    根本原因：标注员对"一段 Notes 的边界"理解不一致，
    有时把相邻文字合并，有时拆分；模型学到的也是混乱信号。

(b) 罕见正交视图样本严重不足
    全数据集中：
      - Auxiliary View:                2 个
      - Detail View:                   5 个
      - Section View:                  9 个
      - Orthographic Rear View:       33 个
      - Orthographic Bottom View:    150 个
      - Orthographic Right View:     179 个
    Rear View 在测试集 4 个全部预测错误（3 个被认成 Front，
    1 个被认成 Top）。

(c) Front 与 Flat Pattern 的语义混淆
    测试集中 5 次 Front 被误判为 Flat Pattern。
    这两类视觉上确实接近（都是平面正投影），
    主要靠是否有折弯线区分。当前 prompt 对此区分不够强。


五、改进建议（按性价比排序）
-----------------------------------------------------------

【建议 1】★★★★★ 把 Group 标签加入训练（最优先）

修改 scripts/qwen3.5-27b_788_with_view/prepare_dataset_swift.py 中
的 FEATURE_CATEGORIES，加入：
  - "Round Hole Group"
  - "Rectangular Hole Group"
  - "Slotted Hole Group"

并在 STEP2_USER_PROMPT 中补充说明 Group 类的含义（一组同类孔
的外接框）。

预期收益：
  - 圆孔/腰孔/矩形孔的图像级准确率从 4-39% 提升到 90%+
  - 不需要重新标注，不需要新数据
  - 只需要重新生成 dataset 并重训练

【建议 2】★★★★★ Notes 标注清理

写一个简单脚本对 788_11Feats_View.json 中的 Notes 标签做：
  - 合并：相邻边界距离小于 W/H 的 5% 的 Notes 合并为一个
  - 过滤：丢掉异常细长（宽高比 > 30）或面积 < 0.5% 图像面积的 Notes
  - 标准化：以最小外接矩形重新计算 bbox

预期收益：Notes 的 F1 从 0.81 提升到 0.90+，从而：
  - view_detection 实例级 F1 从 0.88 提升到 0.93+
  - view_detection 图像级准确率从 36% 提升到 50-60%

如果不想改标注，也可以在评估时对 Notes 单独使用 IoU=0.25 阈值
（其他类仍用 0.4）。

【建议 3】★★★★ 罕见视图过采样

当前 prepare_dataset_swift.py 只做了 RARE_LABELS 的分层划分，
没有做训练过采样。建议在生成训练 jsonl 时：
  - 含 Rear/Bottom/Right View 的图像权重 ×3
  - 含 Section/Detail/Auxiliary View 的图像权重 ×5

或者直接在训练时用 sample_weights 加权。

预期收益：
  - Rear View F1 从 0 提升到 0.5+
  - Right/Bottom F1 从 0.79/0.73 提升到 0.90+

【建议 4】★★★ 加强 prompt 中的视图区分规则

在 STEP1_USER_PROMPT 中明确两条规则：

  规则 A（Front vs Rear）：
    "若图纸中只存在一个'正向投影类'视图，一律标为 Front View。
     仅当 Front 与 Rear 同时存在时才使用 Rear View。"

  规则 B（Front vs Flat Pattern）：
    "若视图中含有任何折弯线（虚线）或折弯标识，必须标为
     Flat Pattern View，即使它位于图纸中央位置。"

预期收益：减少 8-10 个跨类混淆错误，view 实例级 F1 +0.02。

【建议 5】★★ 调整评估指标

不要把"图像级完全匹配率"作为主要指标，因为它对实例数多的任务
天然不公平。建议主指标改用：
  - 实例级 F1（按类别）
  - 实例级 macro-F1（罕见类不被淹没）
  - mAP@0.5（标准目标检测指标）

图像级准确率仅用于诊断"哪些图整体出问题"。


六、不建议的方向
-----------------------------------------------------------

  - 不要重构当前的 13 视图 + 7 特征类别体系，
    现体系下 10/13 视图类已经表现良好。
  - 不要把多轮推理改回单轮，当前的两轮推理（视图 + 特征）
    没有看到明显的容量竞争问题。
  - 不要在 Notes 上加更多损失权重 —— 那只会让模型在错误标注
    上过拟合。先解决标注一致性问题，再考虑权重调整。


七、行动建议
-----------------------------------------------------------

最少代价的两步实验（建议先做）：

  实验 1：在 prepare_dataset_swift.py 的 FEATURE_CATEGORIES
         中加入 3 个 Group 类，重训 1 epoch，重新评估。
         若圆孔/腰孔/矩形孔的图像级准确率显著提升，则验证根因 1。

  实验 2：评估脚本中将 Notes 的 IoU 阈值改为 0.25，
         其他类保持 0.4，重算指标。
         若 view 任务图像级准确率从 36% 跳到 ~55%，
         则验证 Notes 是 view_detection 的主要瓶颈。

两个实验都不需要改动模型，可以在几小时内完成。
