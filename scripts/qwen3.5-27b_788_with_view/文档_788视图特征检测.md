## 一、任务概述

本项目对 **Qwen3.5-27B 视觉语言模型**（VL）进行 LoRA 微调，使其能自动分析西门子风格的工程图纸（钣金件），完成两项检测任务：

1. **第一步：视图与文档区域检测**（13 类）
   识别图纸中各视图区域和文档元素的位置（bbox）

2. **第二步：结构特征检测**（10 类，含孔组）
   在图纸中定位孔、孔组、圆角、折弯、镀银等结构特征，并提取尺寸参数

两步以**多轮对话**形式实现：第一轮输出视图 JSON，第二轮接续同一上下文输出特征 JSON。

## 四、检测类别

### 第一步：视图与文档元素（13 类）

| 大类 | 类别（英文名） | 说明 |
|---|---|---|
| 文档元素 | Title Block | 标题栏，右下角，含零件号/材料/比例等 |
| 文档元素 | Notes | 注释，左下角，含加工要求、公差标准 |
| 正交投影 | Orthographic Projection - Front View | 正视图，主视图，通常最大 |
| 正交投影 | Orthographic Projection - Top View | 俯视图（第一角：正视图**正下方**） |
| 正交投影 | Orthographic Projection - Bottom View | 仰视图（第一角：正视图**正上方**） |
| 正交投影 | Orthographic Projection - Left View | 左视图（第一角：正视图**正右侧**） |
| 正交投影 | Orthographic Projection - Right View | 右视图（第一角：正视图**正左侧**） |
| 正交投影 | Orthographic Projection - Rear View | 后视图，位于左/右视图旁边 |
| 其他视图 | Isometric View | 等轴测图，三维效果 |
| 其他视图 | Flat Pattern View | 展开视图，钣金展开形态 |
| 其他视图 | Section View | 剖视图，含剖面线（如 A-A） |
| 其他视图 | Detail View | 详图，局部放大 |
| 其他视图 | Auxiliary View | 辅助视图，倾斜面投影 |

> **投影法：** 西门子图纸使用 **ISO 第一角投影法**（ISO 5456-2 / GB/T 17452）。俯视图在正视图**下方**，与美国第三角相反。

### 第二步：结构特征（10 类）

| 类别 | 英文名 | 尺寸格式示例 |
|---|---|---|
| 圆孔 | Round Hole | `Ø18`、`Ø18 DP20` |
| 矩形孔 | Rectangular Hole | `□18`、`20x14` |
| 螺纹孔 | Threaded Hole | `M8`、`M8P1LH DP10` |
| 腰孔 | Slotted Hole | `Ø10 20`、`10x20` |
| **圆孔组** | **Round Hole Group** | `4xØ18`、`4-Ø18` |
| **矩形孔组** | **Rectangular Hole Group** | `2x□18`、`3-20x14` |
| **腰孔组** | **Slotted Hole Group** | `2xØ10 20` |
| 圆角 | Fillet | `R3`、`Ø6` |
| 折弯 | Bending | `90° R3` |
| 镀银 | Silver Plating | `105 +5/0` |

**孔组规则：** 多个相同尺寸的孔由统一标注（如 `4xØ18`）描述时，需同时标注：
- 每个**单孔**实例（size 不含数量前缀）
- **整组**的外包围框（size 含数量前缀）

## 五、Prompt 设计

### 系统提示
```
你是一个专业的工业图纸分析助手。请按两步分析工程图纸：
第一步：识别图纸中所有视图区域和文档元素；
第二步：检测图纸中的所有结构特征（孔、圆角、折弯、镀银），提取类别、尺寸和位置。
每一步仅返回 JSON 数组，不附加任何解释。
```

### 第一步 Prompt 关键内容
```
【投影法 — 关键前提】
本数据集所有图纸均采用 ISO 第一角投影法（西门子/德标）。不要假设第三角。
- 俯视图 → 正视图正下方
- 仰视图 → 正视图正上方
- 左视图 → 正视图正右侧
- 右视图 → 正视图正左侧

【识别策略】
1. 先找尺寸标注最丰富的视图 → 这是正视图
2. 以正视图为锚点，按第一角投影法分配其他视图
3. 若图上有等轴测图，可用其验证分类
```

### 输出格式

bbox 为归一化坐标（0-1000 整数，`x_norm = int(x_px / width * 1000)`）。

**第一步（视图）：** `[{"category": "Front View", "bbox": [120, 80, 900, 600]}]`

**第二步（特征）：** `[{"category": "Round Hole", "bbox": [300, 400, 340, 440], "size": "Ø18"}]`

### 6.2 `train_swift.sh` — 训练脚本

**关键参数：**

| 参数 | 值 |
|---|---|
| 基础模型 | `Qwen/Qwen3.5-27B` |
| LoRA rank / alpha | 64 / 128，覆盖所有线性层 |
| 图片 token 预算 | 2560（`IMAGE_MAX_TOKEN_NUM`） |
| 最大序列长度 | 8192（`MAX_LENGTH`） |
| Epochs | 6 |
| 分布式 | DeepSpeed ZeRO-3 |
| `use_logits_to_keep` | **true**（L40S 必须，否则 step 0 OOM） |
| 最优模型指标 | `eval_loss`（不要用 IMMetric，见第九节） |

**启动命令（在 pod 内后台运行）：**
```bash
nohup env TRAIN_CUDA_VISIBLE_DEVICES=0,1,2 \
  bash /workspace/scripts_27b_788_with_view_improve/train_swift.sh \
  > /workspace/logs/train.log 2>&1 &
PID=$!; disown $PID; echo Launched PID $PID
```

Checkpoint 自动保存到 `/workspace/output/swift_27b_788_view_7feats_improve/v<N>-<时间戳>/`，后台 Janitor 脚本自动保留 eval_loss 最优的 5 个。

### 6.3 `metric.py` / `optimizer.py` — 训练插件

- **IMMetric**：训练时用教师强迫方式计算 F1，**不可用于选最优 checkpoint**（见第九节）
- **IMoptimizer**：对 ViT、Aligner、LLM 三部分参数施加不同学习率的 AdamW

### 6.4 `inference_swift.py` — 推理脚本

**运行命令：**
```bash
nohup env PATH=/workspace/venv/bin:$PATH IMAGE_MAX_TOKEN_NUM=2560 \
  python3 /workspace/scripts_27b_788_with_view_improve/inference_swift.py \
  --adapter_path /workspace/output/swift_27b_788_view_7feats_improve/v4-20260510-052936/checkpoint-350 \
  --test_jsonl   /workspace/data/test_view_7feats_improve.jsonl \
  --output_file  /workspace/output/results_v4_ckpt350.json \
  --max_new_tokens 1024 \
  > /workspace/logs/infer.log 2>&1 &
PID=$!; disown $PID; echo Launched PID $PID
```

**输出格式：**
```json
[
  {
    "dataitem_name": "001_....png",
    "result_views":    [{"category":"...", "bbox":[...]}],
    "result_features": [{"category":"...", "bbox":[...], "size":"..."}],
    "raw_views":       "<模型原始文本>",
    "raw_features":    "<模型原始文本>"
  }
]
```

支持断点续跑：相同 `--output_file` 重新运行自动跳过已完成图片。

### 6.5 `evaluate_checkpoints.py` — 批量评估

对某次训练所有存活 checkpoint 逐一跑测试集，输出各 checkpoint 的真实 F1 对比表。
```bash

    --output-dir /workspace/output/swift_27b_788_view_7feats_improve/v4-... \
    --test-jsonl /workspace/data/test_view_7feats_improve.jsonl \
```

### 6.6 `score_results_json.py` — F1 对比

对比任意两个推理结果 JSON 的 F1，纯 CPU，无需 GPU。
```bash

    --test-jsonl dataset/test_view_7feats_improve.jsonl
```

## 九、踩坑记录（重要，必读）

**1. 用 eval_loss 选 checkpoint，不要用 IMMetric**
IMMetric 是训练时的教师强迫指标，峰值过早（step 200），实际最优在 step 350。一定要以 `eval_loss` 最低点为准，必要时用 `evaluate_checkpoints.py` 做真实生成验证。

**2. L40S 训练 27B 必须加 `--use_logits_to_keep true`**
不加会在第一个训练 step 就 OOM（logits 张量约 7 GiB 撑爆显存）。改进版 `train_swift.sh` 已内置。

**3. 推理脚本不能有 `repetition_penalty` 参数**
视觉 token ID 超出词表范围，触发 CUDA device-side assert，导致所有图片全部报错。PVC 当前版本已修复，但如果从本地重新上传脚本要注意确认删掉了这个参数。

**4. 首次在新 Pod 推理需要 3-4 小时 Triton 预热**
切换到新节点后，Triton 要对模型的 CUDA kernel 做自动调优（视觉编码器约 85 min，语言模型约 60 min），期间 GPU 97% 占用但完全没有输出，这是正常的。不要中途杀进程，等待即可。调优结果缓存在 `/workspace/.cache/triton/`，同一 PVC 后续不再重复。

**5. 训练 eval_loss 开始上升就停**
本数据集约 1000 样本，step 300-400 通常是最优点，之后过拟合。看到 eval_loss 连续上升可以直接停训，不用跑满 6 个 epoch。

**6. kubectl cp 大文件超时**
Nautilus 的 websocket 约 30 秒超时，直接 `kubectl cp` 大文件会中途断掉。用并行多文件方式：
```bash
ls dataset/*.jsonl | xargs -n 1 -P 4 -I{} kubectl -n nsf-maica cp {} <pod>:/workspace/data/
```
